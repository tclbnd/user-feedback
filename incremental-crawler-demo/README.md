# 增量爬虫示例

仅使用 Python 标准库，无需安装依赖。需要 Python 3.8+。

## 启动与验收

在项目目录的第一个终端启动服务：

```sh
python3 mock_server.py
```

在第二个终端连续运行两次：

```sh
python3 crawler.py
python3 crawler.py
```

首次运行（尚无数据库和水位文件）输出：

```text
fetched=15 new=13 skipped=2 watermark=2026-01-01T00:00:13.000000Z
```

第二次运行，数据未变，输出：

```text
fetched=15 new=0 skipped=15 watermark=2026-01-01T00:00:13.000000Z
```

`GET /items?page=1` 至 `page=3` 每页返回 5 条数据，包含 `id`、`name`、`price`、`updated_at`。相邻页各重复一个 ID，总计 13 个唯一 ID。范围外的整数页码返回 `[]`，爬虫读到空页后停止。未提供页码时默认第 1 页；非法页码返回 HTTP 400，未知路径返回 HTTP 404。服务的数据和时间戳固定，重启不会改变。

统计口径：

- `fetched`：所有非空页的原始记录总数，包含重复记录。
- `new`：本次实际新增或更新的唯一记录数。同一 ID 保留 `updated_at` 最新的版本，数据库以 ID 为主键。
- `skipped`：`fetched - new`，包含重复记录和被水位过滤的记录。

`crawler.db` 和 `watermark.json` 默认保存在脚本所在目录。SQLite 的 `items` 表存储数据，JSON 的 `updated_at` 字段保存历次抓取的最大时间戳。时间戳统一为 UTC；后续运行只有时间戳**严格大于上次水位**的记录才会写入。等于或早于水位的记录会跳过，包括晚到的旧记录。已有 ID 的新版本会更新对应行。

爬虫仍会抓取所有页，因为接口没有按时间筛选的参数；增量限制应用于数据库写入。所有页面抓取并校验成功后才写库，数据库提交后再原子替换水位文件。抓取失败时退出码为 1；若水位保存失败，重跑会安全去重。

如需重新验证首次运行，请停止爬虫后**同时**删除这两个状态文件，或通过参数指定一对新的状态文件。服务用 Ctrl+C 停止。

## 自定义参数

```sh
python3 mock_server.py --host 127.0.0.1 --port 8001
python3 crawler.py --base-url http://127.0.0.1:8001 --db demo.db --watermark demo-watermark.json --timeout 10
```

`--base-url` 为服务根地址，爬虫自动添加 `/items?page=N`。自定义状态文件的父目录须已存在；数据库和水位文件应配套使用。

## 自动验证

```sh
python3 -m unittest -v
```

测试使用临时数据库，覆盖两次运行的统计、新版本更新、跨页去重、严格水位比较、时区处理、空数据，以及抓取失败和水位写入失败后的恢复。核心测试通过内存传输运行实际 HTTP 请求处理器和响应解析器。

另有真实 HTTP 验收用例：启动随机本地端口，再以子进程连续运行两次 `crawler.py`。如果环境禁止监听端口，该用例会明确显示 `skipped`，这表示真实 HTTP 验收尚未完成；需要在允许本地监听的终端执行上面的启动与验收步骤。
