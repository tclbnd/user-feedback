# 双设备时钟校准

纯 Python 标准库实现（无第三方依赖），解决相机时间戳与录音采样由不同
振荡器驱动、长时间运行产生漂移、设备重启导致本地时间戳重复的对齐问题。

## 目录结构

- `clockcal/model.py`：核心时钟模型。epoch 划分（回拨检测）、稳健仿射
  拟合（MAD + Huber 迭代剔除错配）、连续速率变化的 BIC 分段、有效区间
  与 probe 映射。
- `clockcal/pairing.py`：闪光/声脉冲序列的动态规划配对，以及通用的多
  分段联合最小二乘求解器。
- `clockcal/pipeline.py`：端到端校准。以录音机 epoch 0 为尺度基准构建
  连续参考时钟 R，按事件间隔估计全局事件序号（鲁棒处理缺标与伪峰），
  经二分匹配把两台设备的各 epoch 链接到同一条 R 轴。
- `clockcal/detect.py`：闪光连通段检测（亚帧重心）、500 Hz 音频脉冲的
  相干解调检测，以及一个机制独立的短时 RMS 脉冲复核检测器。
- `clockcal/generator.py`：带真值的素材生成器（独立振荡器、重启、连续
  速率变化、整段缺标、局部伪峰），并渲染帧亮度与分段音频 PCM。
- `clockcal/media.py`：统一时间轴的帧索引清单，以及浮点索引线性插值
  的音频重采样与分段拼接（未校准区间静音并标注）。
- `align.py`：README 约定的 JSON 命令行入口。
- `run_acceptance.py`：两项验收场景的端到端检查。
- `test_rules.py`：回拨、长间隔、重复 tick、错配、外推、缺锚点、速率
  分段的规则单元测试。

## 关键处理规则

1. **回拨 vs 长间隔**：当前 tick 比上一采集位置低超过 0.5 s 判为时钟
   重启，进入新 epoch；单调的长间隔不拆分。重启后本地时钟从接近 0 重新
   计时，同一本地时间戳可在多个 epoch 重复，由 epoch 标签消歧。
2. **乱序与重复时间**：未达回把门限的乱序只记录不拆段；2 ms 内的重复
   tick 合并，参考时刻冲突的重复点交给稳健拟合裁决。
3. **无法配对的标记**：DP 配对的漏检/伪峰走 gap 罚分，未配上的标记只
   记录、不进入拟合；错配标记（误差远大于 1.5 ms 抖动）由 MAD 尺度 +
   硬门限迭代剔除，误配上限 20%。
4. **正常抖动 / 速率变化 / 重启**：抖动由稳健仿射吸收；epoch 内连续的
   速率变化用 BIC + 残差结构检验拆成多段（节点处时间连续）；重启是
   offset 跳变，产生新 epoch，不与速率分段混淆。
5. **有效范围**：相邻可靠锚点间隔超过 90 s 断开，覆盖两端各允许 30 s
   外推；范围外或缺锚点 epoch 的 probe 输出 `null`，缺锚点 epoch 绝不
   沿用旧模型。

## 运行

```bash
# JSON 接口
python3 align.py demo.json output.json

# 两项验收（场景 1 完整素材，场景 2 整段缺标 + 伪峰）
python3 run_acceptance.py

# 规则单元测试
python3 test_rules.py
```

## 验收结果（本机实测）

- 场景 1：40 分钟、每 30 s 对应点共 160 项，已覆盖区间对齐 p95 ≈ 1.4 ms
  （≤ 5 ms），跨重启绝对时间连续、单调，间隔 30.000 s；输出音轨经独立
  脉冲检测器复核 80/80，零误报零漏检，p95 ≈ 0.17 ms。
- 场景 2：移除 9 个连续同步标记并注入 16 个伪峰，移除窗口内全部标记为
  未校准、窗口内无脉冲；正常段 141 个映射点 p95 ≈ 1.5 ms，仍满足门槛。
