# 多轨互相关相位对齐

```
python3 align.py req.json output.json     # 对齐
python3 tests.py                          # 验收测试
```

纯标准库实现（无 numpy/scipy）：自带 radix-2 实数 FFT、带限分数延迟、
WAV 读写。一次运行估算参考轨与所有目标轨之间的延迟、补偿并对齐混音。

## 输入

```json
{
  "tracks": [
    {"name": "ref", "pcm": "ref.wav"},
    {"name": "t1",  "pcm": "t1.wav"},
    {"name": "t2",  "pcm": "t2.wav"}
  ],
  "fs": 16000,
  "max_lag_ms": 20,
  "options": {}
}
```

* 第一条轨道是**时间参考**，其余轨道都相对它估计并补偿。
* WAV：单声道，8/16/24/32-bit PCM。采样率不同会自动重采样到 `fs`（带限 sinc 插值 +
  降采样前抗混叠低通，纯音误差实测 < 1e-4）。
* `max_lag_ms` 同时是延迟搜索范围与补偿上限（可用 `options.max_comp_ms` 单独覆盖）。
* `options` 可覆盖 `analysis.DEFAULTS` 中任意键（帧长、带宽、门限等）。

## 输出

```json
{
  "tracks": [
    {
      "name": "t1",
      "lag_ms": 12.4375,
      "frac_ms": 0.0618,
      "total_lag_ms": 12.4993,
      "reliable": true,
      "conf": 0.9981,
      "coverage_ms": 5888.0,
      "total_ms": 5888.0,
      "drift_ppm": 0.0,
      "curve":     [{"t_ms": 128.0, "lag_ms": 12.499, "lh": 0.78}, ...],
      "segments":  [{"kind": "const", "t0_ms": 0.0, "t1_ms": 5888.0,
                     "lag_ms": 12.4993, "conf": 0.9981}],
      "unaligned": [{"t0_ms": 4736.0, "t1_ms": 5888.0,
                     "reason": "insufficient_overlap"}],
      "compensation": [{"t0_ms": 0.0, "t1_ms": 5888.0,
                        "aligned": true, "lag_ms": 12.4993}]
    }
  ],
  "reference": "ref",
  "mix": "mix.wav",
  "notch_db_improve": 15.1,
  "notch_db_unaligned": 15.1,
  "notch_db_aligned": 0.0,
  "fs": 16000,
  "summary_digest": "9f2c..."
}
```

字段含义：

* `lag_ms` / `frac_ms` —— 偏移的整数采样部分与其亚采样余量（二者之和为完整估计）。
  `lag_ms` 始终对应整数个采样，便于做纯整数移位；`total_lag_ms` 是合并后的精确值。
* `reliable` / `conf` —— 是否可信，以及 [0,1] 的置信度。
* `curve` —— 逐帧延迟曲线（`lh` 为该帧公共信号占比，可作局部置信度）。
* `segments` —— 分段结果：`const`（恒定延迟）或 `line`（含 `drift_ppm` 的时钟漂移）。
* `unaligned` —— **无法对齐**的区间及其原因，绝不静默插值。
* `compensation` —— 实际施加到混音器的整数+小数映射。
* `notch_db_improve` —— 梳状陷波深度的降低量（对齐前 − 对齐后）。
* `summary_digest` —— 只由延迟/置信度/覆盖率计算、按轨道名排序的摘要哈希；
  **随机重排轨道后保持不变**。

`unaligned.reason` 取值：`insufficient_overlap`、`reference_silent`、
`track_silent`、`low_detectability`、`beyond_max_comp`、`unaligned`。

## 算法

四个阶段，分别针对朴素互相关的具体失效模式：

1. **逐帧互谱**（`analysis.frame_xspec`）
   相干加权 + PHAT 白化的 GCC。相干加权用频率平滑的自/互谱估计 MSC，
   抑制只有单轨有能量的频段、噪声主导的频段，以及被混响到达主导的频段；
   PHAT 消除谱倾斜，避免某个响亮的低频段单独决定延迟。

2. **跨帧相干聚合**（`analysis.aggregate_lag`）
   **在逆 FFT 之前**把多帧复互谱相加。不相关的噪声与混响尾会相互抵消，
   直达声同相叠加，因此即使单帧都不可信，聚合后的延迟曲线仍有单一干净峰。
   这是主估计：等效于用一根很长的观测窗分析，同时保留帧级时间分辨率。
   另有一条**短窗**轨迹并行运行——长窗给出低方差数值，短窗把延迟变化
   定位到一帧以内，而不是让长窗把它抹平。

3. **低频主导导致的峰歧义**
   基频强且游走的素材（人声、弓弦、哼声）的延迟曲线会出现相隔一个周期、
   几乎等高的峰簇。单帧常选错周期（实测约 15% 的帧），PHAT 对此无效，
   因为各峰本来就等高。真正起作用的是阶段 2 的聚合：错周期的选择帧间不一致，
   在求和时被平均掉，而直达声持续增强。逐帧峰仅作为置信度中的歧义证据保留。

4. **分段与映射**（`analysis.segment_values` / `map_pieces` / `refine_pieces`）
   把轨迹切成恒定段与线性（漂移）段；**每段的延迟只用该段自己的帧重新聚合**
   得到，避免长滑窗跨越边界时的插值；分段边界取跨变化的两帧中心的中点，
   把边界误差压到半跳以内。任何无法对齐的区间（重叠不足、静音、
   峰不可辨识、补偿超出 `max_comp_ms`）都会被**报告**，而非插值填补。

**可辨识性门限**：以聚合延迟曲线的「峰/背景」比为判据。无关素材约 12 dB
（噪声底），可对齐素材显著高于此值（实测 ≥16 dB）；低于门限的帧记为未对齐，
而不是给出看起来合理却错误的数字。

## 补偿

`compensate.compensate_track` 把延迟拆成两部分：

* **整数**部分按采样索引精确移位；
* **小数**部分用频域线性相位旋转（带限分数延迟），对带限内容精确，
  不会像时域短插值器那样带来高频滚降和模糊。

恒定段整段一次性旋转，因此段内没有任何分块伪影；只有真正时变的段
（漂移斜坡、跳变边界）才切成短块并交叉淡化。未对齐区间保持静音，
不合成样本——否则会重新制造本工具要消除的梳状滤波。

## 确定性

* **分块无关**：分析格点只由 `fs` 与信号长度决定，第 k 帧永远对应绝对采样区间
  `[k*hop, k*hop+frame_len)`。`stream.py` 以增量方式喂同一格点，
  `stream.verify_chunk_invariance` 逐帧断言其与整文件分析完全一致。
* **顺序无关**：`tracks` 按名排序，摘要只由延迟/置信度/覆盖率计算，
  因此任意重排请求都得到相同的 `summary_digest`。
* **重复一致**：同一输入重复运行写出**逐字节相同**的 JSON。

## 验收测量（`python3 tests.py`）

| 项目 | 要求 | 实测 |
|---|---|---|
| 延迟估计误差（单点） | ≤ 0.5 ms | 0.0000–0.0013 ms（干净/含噪/混响/低频主导） |
| 覆盖区间残余延迟（逐窗） | ≤ 0.5 ms | 中位 0.00002–0.00062 ms，最大 0.0016 ms |
| 梳状陷波深度降低 | ≥ 12 dB | 14.9–15.6 dB（单对轨道，干净/含噪/混响） |
| 时钟重启分段 | 两段延迟正确 | 6.00 / 14.00 ms，切换点误差 ≤ 100 ms |
| 两段不同延迟 | 两段延迟正确 | −2.50 / 9.50 ms |
| 时钟漂移 | ppm 正确 | 249.7 vs 250 ppm |
| 分块一致性 | 各分块结果相同 | 512…65536 采样逐帧完全相同 |
| 轨道重排 | 摘要一致 | 4 种排列 digest 相同 |
| 未对齐区间 | 报告而非插值 | 短轨尾部/无关素材/起始静音均正确报告 |

分段切换点的分辨率受帧跳（hop）限制：变化被定位在跨该变化的两帧之间，
因此边界误差约为半个 hop（16 kHz、256 ms 帧下约 64 ms）。

## 模块

| 文件 | 职责 |
|---|---|
| `align.py` | CLI、请求解析、逐轨流水线、混音、验收指标与摘要 |
| `analysis.py` | 逐帧互谱、相干聚合、分段、映射、置信度 |
| `compensate.py` | 整数+分数延迟补偿、混音、梳状陷波测量 |
| `dsp.py` | radix-2 实数 FFT、带限相位旋转、窗函数、WAV I/O |
| `stream.py` | 增量/分块驱动，逐帧验证与批处理一致 |
| `synth.py` | 带真值的合成测试素材（含共享房间混响、长度不等、时钟重启/漂移） |
| `tests.py` | 验收测试套件 |

## 性能

纯 Python，约 1.1× 实时（20 s 素材、4 条轨道约 22 s，单核：4 条目标轨
各做一次配对分析）。FFT 计划与旋转因子在进程内缓存；大批量处理可多进程
并行不同目标轨（每条轨道相互独立）。
