# 按位计数排序的并行前缀和与次序稳定性

`python3 radix.py input.json output.json`

input.json: `{"pairs":[[key32,value]...],"threads":4,"chunk":64,"seed":1}`

模型约定：
- 8 位桶 LSD 基数排序(4 遍),各遍之间相等键保持原始相对次序(稳定)
- 分块计数与全局前缀和解耦,threads/chunk 变化不改变最终排列
- 输出 `{"sorted":[[k,v]],"pass_stats":[{bucket_counts:[256]}*4],"stable_check":bool,"digest":"sha1"}`
- 同一输入乱序分块重放摘要一致

缺陷基线:按 (k,v) 元组排序——等键次序漂移,非基数实现。

## 实现

`radix.py` 是纯标准库实现(无第三方依赖),核心是 4 遍 LSD、每遍一个 8 位字节:

1. **块内计数**(`_count_blocks`):把输入切成固定块,每块独立算 256 桶直方图。
   任务按 `seed` 派生的乱序提交,结果按 `block_id` 归档——完成顺序不参与任何决策。
2. **全局前缀和**(`_global_counts_and_starts`):严格按 `block_id` 升序累加,
   与前一步的线程调度彻底解耦。这一步只读 `hists`,不改数据。
3. **块级写入基址**(`_block_base_offsets`):`base[b] = 桶起点 + 前面各块在该桶的元素数`。
   各块的写区间互不相交,因此散射可并行且与调度无关。
4. **稳定散射**(`_scatter_blocks`):每块按源下标递增写自己的区间;
   由于块号升序拼接到全局桶,相等数字保留本遍输入的相对次序。
5. **逐遍校验**(`_pass_is_stable`):记录每个元素在本遍输入序列中的源下标,
   要求每个桶内源下标严格递增。4 遍都为真且最终键非降,`stable_check` 才为 `true`。

`threads` 只控制线程池宽度,`chunk` 只控制块划分粒度(输入很大时会内部下限抬升以限制
块元数据内存,仍是同一排列),`seed` 只改变块任务的提交顺序。三者都不改变最终结果。

`digest` 沿用基线口径 `sha1(str([(k, v), ...]))`,但流式拼接,不额外构造大字符串。

## 测试

`python3 test_radix.py`(加 `--large` 跑百万级)。覆盖:

- 4 组分布 × `threads∈{1,4,8}` × `chunk∈{64,4096}` × 3 个种子,与
  `sorted(key=key)` 参考稳定排序逐位对照(键与伴随值),并核对
  `stable_check` 为真、4 遍桶分布各 256 桶且总和为 n、摘要与参考一致且不漂移。
- 边界:空输入、单元素、`0` 与 `2**32-1`、非可比较伴随值(含 `None`/`dict`/`list`)、
  `chunk` 大于输入长度。
- CLI 端到端:三种参数组合的输出文件逐字节一致。

`python3 test_fuzz.py` 额外做:

- 400 轮差分模糊(随机规模/分布/线程/分块),全部与参考一致且摘要唯一。
- 两个变异测试,确认校验位真能抓缺陷:(1) 块内散射逆序 → 排列仍正确但
  `stable_check` 变假;(2) 前缀和按块完成顺序逆序汇总 → 排列错误且 `stable_check` 变假。
